# DocxSpec Studio V2 详细设计与实施方案

- 日期：2026-11-16，Asia/Shanghai。
- 设计选择：方案 3，左侧模板集导航、中间文档、底部组件库、右侧对象属性。
- 代码参考：远程 main 的 b02361f，包含 DS 母版样式、章节结构和可选 Word COM 刷新。
- 文档状态：设计与技术决策草案，尚未实现 V2，也未承诺未经验证的 WPS 自动化能力。
- 核心验收目标：用户能理解“选中什么、修改什么、最终输出什么”，编辑后的真实预览与下载的文件来自同一次生成。

## 1. 产品定义与关键决策

用户先创建模板集，在集合中创建模板；从组件库拖入标题、正文、表格、图片、题注或复合组件，选择组件后修改属性，也可以另存为新的组件。已有报告通过 AI 分析为固定内容、字段、重复结构和条件内容，自动创建同样可编辑的模板草稿。

所有默认输出样式来自受控 DS 母版。AI 导入的原报告只提供内容、结构线索和可选样例数据，不成为渲染母版，不携带源文档的字体、颜色、主题、编号定义及页面布局。

最重要的技术决策：

1. **中央主画布改为真实排版预览。** 模板模型先生成 DOCX，再由用户选定的目标 Office 引擎排版并导出 PDF，前端显示这个 PDF。
2. **模板结构是唯一编辑数据源。** PDF 是模型的一次真实呈现，不作为可随意修改的编辑数据。
3. **预览与下载绑定一个不可变生成结果。** 不能预览文件 A，下载时重新生成文件 B。
4. **选择目标引擎。** Microsoft Word、不同版本 WPS、LibreOffice 不能被视为排版完全等价。必须显示本次预览由哪个引擎产生。
5. **暂不承诺 Word 式任意位置直接打字。** 默认通过对象选中、属性面板和局部内容编辑修改，确认后由真实引擎更新画面。若要求完整原生编辑体验，必须增加 Office 扩展路线。
6. **先做排版与定位技术验证，再扩展完整 UI。** 如果真实页面无法稳定更新和定位，不能用漂亮的 HTML 页面作为交付替代。

## 2. 为什么当前显示会与输出不同

当前浏览器依赖 HTML/CSS 布局，输出依赖 DOCX 和 Office 排版。即使使用相同字体名称，两者仍有不同的文字度量、换行、表格最小行高、段落间距、跨页规则和字段计算机制。

| 差异来源 | 常见现象 | V2 处理方式 |
| --- | --- | --- |
| 字体缺失或替换 | 行数、页数改变 | 在渲染机器检查字体，展示替换项；严格模式下拒绝标记验收通过 |
| HTML 与 Office 的行布局 | 浏览器一行，Word 两行 | 中央主视图使用 Office 导出的 PDF |
| 页眉页脚、分节、首页不同 | 正文起点与页数不同 | 建模各节和故事区域，交由 Office 排版 |
| 表格合并、行高、跨页 | 单元格切断、标题留在前页 | 使用真实 DOCX 表格规则，并检查目标引擎结果 |
| 标题编号、题注、目录和引用 | 编辑视图编号与文件不同 | 编号由文档模型/Office 字段产生，真实结果回显 |
| 示例值与实际值长度不同 | 样例两页，实际五页 | 预览绑定明确的数据版本，换数据必须重新预览 |
| Office 版本或字体版本不同 | 本机与其他机器不同 | 保存引擎和字体环境摘要，不承诺跨机器逐像素一致 |

复制更多 Word 样式到 CSS 可以改善编辑控件的观感，但不能解决这些根本差异。

## 3. 一致性应如何定义

### 3.1 产品保证范围

在相同模板版本、组件版本、母版版本、数据、资源、渲染选项、目标引擎及字体环境下：

- 中央展示的是该生成结果的真实页面。
- 下载 DOCX 是对应结果中已保存的那个 DOCX。
- 下载 PDF 是中央展示的那个 PDF。
- 用户修改后，在新结果准备好之前，界面明确显示“正在更新，当前仍为上一版本”。
- 导出按钮不能把旧版本文件伪装为当前版本；必须等待、报错，或由用户明确选择下载历史版本。

PDF 显示的是目标引擎导出/打印时的版式，不包含 Office 的光标、标尺、编辑标记和屏幕缩放行为。其他电脑再次打开并更新域后可能重新分页，属于不同渲染环境。

### 3.2 不做的虚假保证

- 不保证同一 DOCX 在 Word 与 WPS 中逐像素一致。
- 不把“设置打开更新标记”当成“所有域刷新完成”。
- 不把浏览器排版图标、字体下拉框与真实分页之间的关系当作已验证。
- 不以未渲染的 HTML 示意页替代失败的 Office 预览。
- 不用对源报告的截图或 PDF 覆盖层宣称已实现原生 Word 文档编辑。

### 3.3 目标引擎策略

每个模板集配置默认目标引擎，模板可以明确覆盖。推荐首先实现 Windows 本机 Microsoft Word 渲染适配器，因为现有代码已有可选 COM 路线。若用户日常交付以 WPS 为准，应选择 WPS 并验证该平台的自动化适配器，不能默认用 Word 或 LibreOffice 代替后标记为 WPS 预览。

无可用引擎时，可编辑模型并生成未经实际排版验收的 DOCX；主视图必须标明预览不可用。不能偷偷切换引擎。可提供“在目标应用中打开”检查入口。

### 4.1 模板集与模板管理

- 首屏创建模板集，设置名称、说明、DS 母版版本和目标引擎。
- 集内模板列表支持新建、复制、重命名、移动、归档、版本恢复。
- 新建模板支持“空白正文”和“DS 默认结构”；两者均使用 DS 样式。
- 母版的封面、修改记录、目录等可作为初始组件，但不能将示例章节固定为用户无法修改的业务结构。
- 左栏切换模板前，先保存草稿；保存失败时保留当前内容，不静默丢弃。
- 多模板标签页与模板集导航都引用真实模板 ID，不能仅靠当前数组位置决定编辑目标。

### 4.2 选择与编辑

- 单击页面对象，右侧显示该对象的准确属性。
- 文档结构树是始终可用的精确选择入口，用于小对象、页眉页脚、重叠或无法准确定位的对象。
- 对象路径如“正文 / 用例重复块 / 表格 / 第 2 行 / 第 3 列”，允许逐级选中。
- 双击文本对象打开局部内容编辑器或右侧内容编辑区。编辑区强调“正在编辑内容”，确认后关闭并更新真实页面。
- 常用纯文本可支持原位输入浮层，但输入期间的临时换行仅为辅助；关闭浮层后，以新真实预览为准。
- 不允许在 PDF 空白区域随意打字，再猜测应该修改哪个 Word 段落。
- 表格选择区分表格、行、列、单元格；选中单元格可以修改内容、对齐和合并规则，整表属性控制宽度与边框。
- 页眉页脚通过结构树或页面定位进入，属性显示所属节、首页不同、奇偶页不同、与上一节链接状态。
- 没有选中对象时显示模板/页面属性，不显示上一个对象的属性。

### 4.3 拖拽行为

流式文档的拖拽表达结构顺序和容器归属，不表达自由页面坐标。

- 拖入时在有效对象边界显示插入线，例如“插入到第三章正文后”。
- 拖入表格或重复块时，显示进入的容器名称。
- 不能可靠识别页面落点时，允许拖入结构树或选择“插入到当前对象之后”。
- 拖入标题可修改级别；标题所归属的下级内容在结构视图中明确表达，移动整章与仅移动标题文字是不同命令。
- 表格题注与目标表格通过稳定 ID 关联，移动表格时保留关系，编号重新计算。
- 输入过程中积累修改只触发一次合并渲染，避免每个按键都调用 Office。

### 4.4 预览状态必须可见

主视图需要：未生成、排队、生成中、当前版本已就绪、旧版本、失败、引擎不可用等状态。

页码来自真实 PDF，不由浏览器猜测。状态栏显示预览版本、数据集名称、引擎及生成时间。页面变动后维持选中节点，重新定位其新位置，不机械保留旧页码。

“生成报告”先校验数据与模型，再取得当前输入对应的渲染结果；结果页提供 DOCX/PDF 下载、字段更新状态和引擎信息。

## 5. 组件与样式体系

### 5.1 组件类型

| 类型 | 编辑内容 | DS 默认与特有属性 |
| --- | --- | --- |
| 标题 | 文字/字段混排、级别 | DS 1—6 级标题，编号和段落规则 |
| 正文/列表 | 富文本、字段、列表项 | DS正文及受控列表规则 |
| 表格 | 行列、单元格、合并、数据绑定 | DS表格表头/DS表格文字，宽度、边框、跨页 |
| 图片 | 固定资源或图片字段 | DS图片，对齐、比例、最大尺寸 |
| 表/图题注 | 文字、关联对象、编号 | DS题注，表前/表后或图上/图下 |
| 重复区块/重复行 | 子结构、数据源 | 每条数据复制结构，保留对象实例身份 |
| 条件区块 | 条件、缺失处理 | 声明式规则，不执行用户代码 |
| 目录/图目录/表目录 | 范围、标题级别 | DS目录和 Office 域结果 |
| 封面/修改记录/签署区 | 组合内容和字段 | 来自母版的可编辑复合组件 |
| 分页/分节 | 页面属性和区域关系 | DS 页面默认设置，可显式覆盖 |
| 页眉/页脚 | 文本、页码、图片 | DS页眉/DS页脚，所属节及继承关系 |

“所有东西能编辑”在本方案中指上述受支持对象和属性，不等于任意历史 DOCX 中所有复杂 Office 对象均可无损编辑。公式、浮动文本框、SmartArt、嵌入 Excel、修订和批注等须单独定义支持等级，不能静默丢失。

### 5.2 样式继承

DS 母版 → 组件定义覆盖 → 当前实例覆盖。

属性面板逐项标明继承值和已修改值。字号以 Word 的 pt 为规范值，中文字号作为别名；厘米/毫米和 pt 在前后端统一转换，不以 CSS px 作为输出规范。

- 内置组件只读，用户可修改实例或另存为新组件。
- 自定义组件修改生成新版本；已有模板固定其引用版本，只有显式升级才变化。
- 实例修改不能覆盖全局同名 DS 样式。输出为受控的 DS 派生样式或局部格式覆盖，并保留基础样式关系。
- 标题保留正确的 outline level 和编号关联，不能只把外观改成粗体大字。
- 表格与图片题注分开编号，关联对象 ID 与题注 ID 均稳定。
- 母版/组件升级时提示影响范围，可生成新旧预览比较，不原地覆盖历史输出。

## 6. 技术路线比较与推荐

| 路线 | 优势 | 限制 | 本方案定位 |
| --- | --- | --- | --- |
| HTML/CSS 模拟 Office | 浏览器编辑顺滑、开发快 | 分页与输出不能可靠一致 | 仅用于局部内容输入与结构视图 |
| Office 生成 PDF＋对象属性编辑 | 页面来自真实引擎；复用 DocxSpec | 有渲染延迟；自由文字编辑受限 | **V2 默认路线** |
| Microsoft Word 加载项/任务窗格 | 原生页面和文字编辑体验 | 安装、平台及 API 能力限制；WPS 不自动兼容 | 需要原生编辑时的后续路线 |
| 嵌入第三方在线 Office 编辑器 | 浏览器内提供完整文档编辑 | 服务部署/许可；其排版不等同于桌面 Word/WPS | 不作为一致性承诺的捷径 |
| WPS 专用 SDK/扩展 | 可接近目标用户日常工具 | 依赖平台、版本、授权与 API 可用性 | 完成能力验证后单独接入 |

如果产品最终要求“中央自由输入、拖动、分页都与 Word 一模一样”，应升级到 Word 原生扩展路线，组件库与模板集管理放入任务窗格。不能仅给 PDF 添加光标就宣称实现了这一目标。

## 7. 推荐技术栈

| 层 | 技术 | 选择原因/约束 |
| --- | --- | --- |
| 前端应用 | React + TypeScript + Vite | 拆分状态与组件，替换单文件 DOM 重绘 |
| UI 控件 | Radix/同类无头可访问组件 + 项目样式 | 统一对话框、菜单、键盘和焦点行为；不强制套用现成视觉主题 |
| 拖拽 | dnd-kit | 组件排序、容器投放、键盘替代操作 |
| 内容输入 | Tiptap/ProseMirror | 局部富文本及表格内容编辑；不承担真实分页 |
| 状态 | Zustand 或小型命令状态层 | 唯一文档树、选择状态和可撤销命令；服务端数据通过查询层管理 |
| 真实预览 | PDF.js | 页面渲染、缩放、文本层、坐标转换；DOM 选择层单独管理 |
| Python API | FastAPI + Pydantic | 版本化模型、校验、任务接口；保留 Python 渲染核心 |
| 数据库 | SQLite + SQLAlchemy + Alembic | 本机部署、事务、模板版本、明确迁移 |
| 文件存储 | 本机内容哈希资源目录 | 图片/源文件/DOCX/PDF 独立保存，数据库记录元信息 |
| DOCX 编译 | DocxSpec + python-docx/docxtpl | 复用受控 DS 母版、样式及编号能力 |
| 渲染任务 | 独立进程 worker + SQLite 持久任务表 | 避免在 HTTP 请求线程中运行 Office；首版不要求 Redis |
| Word 适配器 | Windows + pywin32 + 安装的 Word | 交互式本机用户会话；不把它包装成通用无人值守云服务 |
| WPS 适配器 | 按平台验证的官方 API/SDK | 需专项验证；没有稳定接口时只提供显式手动检查流程 |
| AI | 服务端模型供应商适配器 + 严格结构校验 | 支持用户配置本地/外部模型；AI 只产生声明式模型 |
| 测试 | pytest、Playwright、Office 集成测试、PDF 文本/图像对比 | 同时验证状态、文件结构和真实排版 |

具体依赖版本在技术验证通过后锁定。是否使用带商业许可的编辑扩展必须提前检查，不将付费能力视为默认免费依赖。

保持本机应用形态：开发时 Node 构建前端，发布包由 Python 服务提供静态资源，普通用户无需单独安装 Node。Windows 安装器与引擎诊断工具可以在功能稳定后增加。

## 8. 数据模型

### 8.1 主要实体

- TemplateSet：名称、说明、母版版本、默认引擎、共享字段定义。
- Template：归属集合、名称、状态、当前草稿版本、已发布版本。
- TemplateRevision：不可变组件树、schema 版本、组件引用、母版引用。
- ComponentDefinition / ComponentVersion：类型、DS 样式角色、默认属性、子节点结构、公开参数。
- DocumentNode：稳定 ID、类型、内容、覆盖属性、数据绑定、子节点。
- DocumentSection：页面尺寸、边距、分栏和页眉页脚故事区域。
- FieldDefinition / DatasetDefinition：类型、显示名、必填、缺失策略、重复元素结构。
- DataRevision：本次报告值与样例数据；不混入组件默认正文。
- Asset：内容哈希、类型、尺寸、用途、资源引用。
- ConversionJob：源报告、分段分析、识别候选、来源定位、结果模板。
- RenderJob / RenderArtifact：输入指纹、任务状态、引擎摘要、产出文件、定位映射、诊断信息。

模板 schema 升为 V2。数据库 schema 版本与模板文档 schema 版本分开演进。

### 8.2 文档节点示例

以下为概念模型，不是要求用户填写的 JSON 界面：

    文档
      第 1 节：封面，首页页脚
      第 2 节：正文，共享页眉页脚
        一级标题：测试结果
        正文：项目名称字段＋固定说明
        重复区块：testCases
          二级标题：case.name
          表格：步骤、预期、实际、结论
          图片：case.screenshot
          图题注：关联上述图片

节点位置不能依赖数组下标。重复生成的实体使用 nodeId + 稳定记录 key + occurrenceId 区分，避免用户点击第三个样例却修改了错误组件。

## 9. 真实渲染流水线

### 9.1 一次修改到预览的完整过程

1. 前端发出文档命令，更新本地模型及选中状态。
2. 服务端保存草稿，使用版本号防止多窗口覆盖。
3. 输入停止后合并调度预览任务；连续操作只保留最新待执行版本。
4. 固定本次模板、数据、组件、母版和资源版本，计算输入指纹。
5. 校验字段与结构，将组件树编译为 DOCX；从受控 DS 母版创建，绝不从源报告样式创建。
6. 在 DOCX 中加入不影响正文显示的内部定位标记，为组件和数据实例建立锚点。
7. 独立 worker 使用指定引擎打开，检查转换/字体问题，处理允许的域并重新分页。
8. 保存最终 DOCX，再从同一打开文档导出 PDF；关闭时不能再次静默改写文件。
9. 核对文件存在、可读取、页数、字段诊断和输入版本，记录文件哈希与引擎版本。
10. 写入不可变生成结果，通知前端加载 PDF 和定位映射。
11. 前端仅应用与当前输入版本一致的结果；过期任务可以保留历史，但不能覆盖新预览。
12. 下载直接返回该结果中的文件，不再次调用生成器。

不同文件打开/导出操作的具体顺序必须在目标引擎验证。若导出会修改文档状态或触发再次刷新，应重新保存并核对，不能仅依据 API 成功返回认定两个文件一致。

### 9.2 引擎适配器能力契约

    detect()              平台、版本、字体/权限、可用能力
    render(docx, options) 返回最终 DOCX、PDF、诊断和映射能力
    cancel(job)           尽力取消任务
    health()              当前是否可接受任务

能力标记至少包括：PDF 导出、实际域更新、分页查询、锚点页码、对象区域定位、并发能力。WPS 的具体实现必须依据本机已验证 API；GUI 点按钮可用于验收，但不作为稳定生产渲染 API。

Worker 按实际许可和稳定性限制并发，首版一个 Office 实例一次处理一份文件。任务有超时、取消、独立工作目录和清理逻辑；超时只终止本应用拥有的 worker/Office 进程，不能结束用户正在编辑的 Word/WPS。

不要把 Windows Office COM 放入普通 Web 请求线程，不把它部署成无交互桌面的通用 Linux 服务。

### 9.3 域刷新与稳定性

- 标题/序列、目录、图表目录、正文、各节页眉页脚及受支持文本框分别处理。
- 检查 API 错误和返回值，明确记录哪个故事区域失败。
- 更新后重新分页，再更新依赖页码的目录和引用；需要时进行有限次数的收敛检查。
- 以结构化字段结果、目录页码和页面数判断稳定，不比较含时间戳的整个 DOCX 字节是否完全相同。
- 收敛失败、超时或某区域不支持时返回真实失败/部分结果，不能改称成功。
- 页脚 PAGE 域共享在多页重复显示，XML 中一个缓存值不能代表所有页面；应逐页检查实际 PDF，而不是机械要求单个页脚 XML 同时包含所有页码。
- 专项测试中故意注入的旧缓存应单独追踪；PDF 正确与所有区域缓存均更新是两个不同的验收项目。

历史 WPS 测试已说明仅设置 updateFields 或仅在正文 Ctrl+A/F9 不足以保证全部域缓存完成刷新。这是风险依据，不替代 V2 或新母版版本的重新验收。

## 10. 页面对象定位：必须先验证的难点

PDF.js 负责显示页面，本身不知道某段 PDF 文字对应哪一个模板组件。源 DOCX 与 PDF 之间需要显式映射。

### 10.1 定位标记

为可定位节点和重复实例生成稳定的 Word 书签或受支持内容控件锚点，保存节点与锚点之间的关系。书签名称要满足 Office 长度/字符限制，使用短 ID 映射，不直接塞入完整数据路径。

锚点不能作为可见占位文字进入报告，不能改变原文样式、段距、表格行高或页数。必须测试目录/字段更新后锚点仍有效。

### 10.2 分级定位能力

- 第一级：结构树节点 → 实际所在页或页区间，足以跳转查看。
- 第二级：节点 → 页面上的准确区域；支持单击真实页面选中对象。
- 第三级：表格单元格、跨页组件、多段富文本和页眉页脚实例的精确区域。

Word 的 Range/分页查询可辅助确定页码与位置，但不能假设一个 Range 就对应一个矩形。跨页表格、换行文本和重复页眉需要多个区域。

必要时结合 Office 文本范围与 PDF 文本位置进行匹配。重复文字、多列、隐藏字符、连字或文字被转成路径时不能依靠简单字符串搜索。匹配有歧义则回退到页级定位和结构树，不画一个看似精确但错误的边框。

### 10.3 输出映射

每条映射记录：模板节点 ID、实例 ID、故事区域、页码/页区间、可选多个矩形、定位等级、引擎与生成版本。

前端必须使用 PDF 页坐标转换处理缩放与旋转；选中框和正文共用同一页变换，不能通过固定像素猜测位置。

**这是 P0 技术验证的放行条件。** 若目标引擎只能稳定给出页码，首版交付必须明确采用“结构树选择＋真实页面查看”，不能宣传“页面任何对象都可准确点选”。

## 11. AI 转化模板

### 11.1 流程与界面

在模板集点击“AI 转化模板”，选择 DOCX 后创建转换任务。左侧显示源内容或可用的原文件真实预览，右侧显示生成的 DS 模板预览。

AI 自动生成模板草稿，不要求用户逐一创建组件；无法确定的内容标记待确认。用户可以将候选转换为固定文字、单值字段、重复数据或条件内容，再进入同一组件编辑器。

来源对照页展示“识别理由＋原文位置＋建议字段”，不要用无校准的置信度百分比冒充可靠性。无法识别时保留内容，不静默删除。

### 11.2 解析与生成

1. 本地提取正文、表格结构、图片、题注线索、标题层级、页眉页脚内容及源位置。
2. 源格式可以用于判断内容类型，但不进入目标样式。
3. 按结构切块，识别固定内容、字段、重复表格/重复行、图片槽位、题注及引用关系。
4. 模型返回受控组件树和字段定义，不返回任意可执行代码或自由样式定义。
5. 校验允许的节点、数据路径、循环、DS 样式角色和引用完整性。
6. 自动创建模板草稿并保存到所选模板集，样例值另存为 DataRevision。
7. 使用 DS 母版和样例数据真实渲染，供用户对照修正。

例如：项目名称变为单值字段，多张同结构用例表变为一个重复块；通用说明默认保持固定文字。仅一份报告不能证明某内容永远不变，结论和判定规则需要明确确认。

源文件中即使存在名为 DS正文 的样式，也不能优先于受控母版。保留图片内容与继承图片原版式是两回事；图片按目标组件的尺寸与对齐规则重新排版。

### 11.3 模型连接及失败处理

AI 供应商与密钥由服务端管理；支持本地模型和外部服务配置。在开始分析前明确展示所用模型与哪些内容会发送，不能默认把整个报告、附件和隐藏内容上传。

解析失败、模型不可用、结构校验失败和部分识别成功分别呈现；允许取消、保留部分草稿、按失败段重试。文档中的指令、宏和链接都是输入内容，不能自动执行。

## 12. API 与任务状态设计

建议接口边界（具体路由可在实现时统一）：

| 接口组 | 主要操作 |
| --- | --- |
| /template-sets | 创建、列表、重命名、归档、引擎/母版配置 |
| /templates | 创建、读取、复制、移动、草稿保存、版本恢复 |
| /components | 内置/集合组件列表、另存、版本更新、升级差异 |
| /assets | 上传、校验、读取、引用与清理 |
| /datasets | 字段定义、样例/真实数据校验及版本 |
| /conversions | 上传报告、开始分析、进度、候选修正、草稿结果 |
| /renders | 创建任务、合并请求、取消、状态、诊断 |
| /artifacts | 指定结果的 DOCX/PDF、页面信息、定位映射 |
| /engines | 能力探测、版本、字体环境与健康状况 |

草稿保存使用 revision/ETag 防止覆盖。渲染任务状态建议：queued、compiling、rendering、validating、ready、failed、cancelled、superseded。SSE 推送进度，轮询作为降级；不要把响应断开直接视为任务失败。

任务失败时保留最近成功预览，但加明显旧版标识。前端不得因为接口返回 200 就显示“全部域更新完成”，必须读取具体产物和诊断状态。

## 13. 性能、保存与故障恢复

- 内容输入即时写入本地编辑状态，短暂防抖保存草稿；网络失败保留可恢复副本。
- 撤销历史记录编辑命令或差量，避免每个字符复制所有图片和完整文档。
- 图片资源通过 ID/哈希引用，不把大段 base64 放入每个草稿与撤销快照。
- 真实渲染按输入停顿合并，支持手动“立即刷新”。初始防抖可从 800—1500ms 试起，以实际设备体验调整。
- 缓存键包含模板/数据/组件/母版/资源/渲染选项/引擎版本和字体环境摘要，不跨引擎复用。
- 小报告暖启动渲染目标可暂定 5 秒以内，复杂报告显示进度。该数值必须通过 P0 基准测试确认，不作为尚未实测的承诺。
- 大文档使用页面虚拟列表；不是所有页都同时栅格化。PDF.js 文字层和定位层按可见页加载。
- Office 弹窗、启动挂起、超时和进程退出均有可见错误，提供重试和打开诊断；不无限自动重试。
- 清理只处理本应用创建的临时文件和进程；源报告、用户的 Office 会话和已完成历史输出不受影响。

## 14. 迁移与代码组织

保留用户已推送的 DS 母版和现有 DocxSpec API，不回退到早期样式方案。

建议结构：

    studio/
      web/                 React 应用、组件、PDF 页面、状态命令
      backend/
        models/            文档/组件/字段 schema
        services/          模板、组件、资源、版本服务
        compiler/          V2 模型到 DocxSpec
        engines/           Word/WPS/其他显式适配器
        jobs/              调度、取消、超时和任务状态
        ai/                解析、识别、供应商适配、结果校验
        storage/           SQLite 模型、迁移、资源存储
      tests/               API、模型、浏览器和引擎集成测试

实际迁移时逐步拆分，避免一次重写失去现有生成能力。

旧 v1 模板迁移成独立组件树；原章节、图片、覆盖样式和数据保留，固定测试区转换为重复组件。迁移创建新记录/新版本，不覆盖旧数据库。先比较文字、图片、表格和真实预览，再确认切换。

源码仓库提交可复现夹具生成器与测试，小型必要夹具可入库；Office 安装包、模型密钥、本机数据库、真实用户报告和临时产物不入库。

## 15. 实施阶段与放行条件

### P0：真实排版与对象定位验证

工作：运行母版＋代表性组件生成；Word 适配器；WPS 能力探测；真实 PDF；节点页码/区域映射；同一次产物下载；超时取消。

夹具覆盖：中文段落、各级标题、长表格、合并单元格、重复表头、截图、题注引用、目录、多节页眉页脚、重复块。

放行：至少一个目标引擎可稳定生成、预览、下载同版本文件；明确各对象可达到的定位等级；完成字体/引擎诊断；无弹窗被忽略。如果主要目标是 WPS，则 WPS 路线必须通过对应验证，否则先调整产品部署路线。

### P1：模板集与组件编辑基础

工作：方案 3 界面、模板集、版本、组件定义/实例、标题/正文/表格/图片/题注、属性、结构树、拖拽、撤销、另存组件。

放行：选择准确、修改范围准确、默认样式来自母版、保存重开一致、现有模板不被组件更新静默影响。

### P2：完整自动化模板模型

工作：字段、重复行/块、条件、样例与真实数据、分节、页眉页脚、目录、输出诊断、迁移。

放行：多个数据集和多个重复区可正常输出；长数据真实分页可见；必填缺失、引用错误与不支持对象有明确反馈。

### P3：AI 转化模板

工作：解析、结构识别、草稿生成、来源对照、候选确认、受控样式映射、失败重试。

放行：源样式不能污染输出；重复数据不会被写死；不确定内容不丢失；转换结果可用手工组件继续修改。

### P4：目标引擎验收与交付

工作：完整操作回归、目标机器 Word/WPS 真实打开/保存/重开/PDF 测试、性能与恢复测试、使用文档、安装与诊断。

放行：按引擎分别出具结论。不能以 Word 通过代替 WPS 通过；不能以旧版母版的历史证据替代当前代码验收。

排期应在 P0 结束后估算；对象精确定位和 WPS 自动化是主要不确定项，不预先把全部范围压成几天的 UI 改造。

## 16. 验收清单

### 编辑与组件

- 新建模板集和多个模板，数据与内容隔离；关闭重开仍可编辑。
- 拖入组件出现明确插入位置；点击与键盘插入同样可用。
- 标题、表格、单元格、题注、图片、页眉页脚选择准确。
- 修改仅影响选中范围；恢复默认、另存组件、版本升级、撤销重做正确。
- 未失焦时刷新不丢文字；保存失败、容量限制和多窗口冲突可恢复。

### 真实预览与输出

- 使用固定的模板、数据、母版、资源、引擎和字体环境。
- 预览结果 ID 与下载结果 ID 相同，DOCX/PDF 哈希可追溯。
- 修改后显示旧版/更新中状态，旧任务结果不会覆盖新版本。
- 中文字体、标题编号、表格尺寸、跨页、图片、题注和各节页眉页脚正确。
- 人工在目标应用中重新打开最终 DOCX，再导出 PDF，比对内容、页数、换行和布局。
- 页面图像比较统一 DPI、裁切和颜色设置；允许抗锯齿噪声，不允许缺字、错页、表格截断或编号错误。阈值由基准样例确定，不能随意放宽以通过测试。
- 缺字体、引擎不可用、域刷新失败和超时均不能被标为完整成功。
- 正文、目录、引用和页眉页脚分别检查；不将页脚单一 XML 缓存等同于所有页的实际页码。

### AI 转换

- 使用故意不同字体/颜色/页布局及同名伪 DS 样式的输入，输出仍为受控母版样式。
- 多条相同结构记录转换成重复块/行，换一组数据仍可正确生成。
- 普通说明不被全部错误改成占位，业务结论不会被 AI 编造。
- 合并表格、图片和题注来源可追溯，未支持内容明确标记并保留处理选择。
- 生成模板可手工继续编辑、另存组件、保存重开。

## 17. 推荐先确认的产品边界

本方案按以下默认值设计，可在开工前调整：

1. 第一优先级为“真实输出可见、组件修改明确”，允许局部内容编辑后等待预览更新，不要求一次实现完整 Word 原生自由编辑。
2. Windows 本机 Word 是首个工程验证适配器；最终主要交付若使用 WPS，必须把对应 WPS 版本设为目标并完成 P0，不以其他引擎替代。
3. DS 母版是唯一默认样式来源，自定义组件可在其上显式覆盖；AI 不继承源文档版式。
4. 先提供本机单用户应用，AI 模型可配置；联网多人协作与云端 Office 自动化不进入首版。

若第 1 条不符合实际期望，应在 P0 前转向 Office 原生扩展路线，而不是继续投入 HTML 模拟分页。
