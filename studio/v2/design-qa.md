日期：2026-11-17。基准：用户选定方案 3，后续要求以真实 Office 排版预览替换模拟文档。检查的是运行中的页面截图，不是设计图或 HTML 页面拼接截图。

## 视觉检查

- 采用左侧模板集/结构树、中央文档、底部组件库、右侧属性栏的布局；DS 标识、蓝色选择态与主操作保持一致。
- 1440 × 1000 Chromium 截图中三栏清晰，底部组件库固定在工作区，右侧属性可独立滚动；真实 PDF 内文字选中框可对应到属性对象。
- 方案图中的假文档占位、伪分页、固定选框被真实 PDF 页面替换。只有唯一文本匹配显示可选区域，表格/图片使用结构树，不捏造几何定位。
- 与设计图的剩余差异：没有多模板标签页，组件库用横向列表而非分类标签；新建名称仍使用浏览器对话框；窄屏将属性栏移到下方，当前没有完整的移动端验收。

## 实际执行验证

- 本机 Chromium 真实操作：创建模板集/模板，点击与拖入组件，修改字号与文字，保存自定义组件，保存模板，重新加载后打开，验证内容持久化。
- 实际调用 LibreOffice 25.2.3.2，生成 DOCX 与 PDF，在浏览器用 PDF.js 展示；下载文件的 SHA256 与同任务 manifest 一致。
- 修改内容后显示旧预览提示、禁用当前 DOCX 下载。未配置 AI 时上传入口禁用并说明配置方式。浏览器执行无 pageerror。
- 额外真实 Office 多页测试：12 个重复用例、表格题注、图片及图片题注，生成至少 3 页；逐页检查 PAGE/NUMPAGES，检查最终表格编号、图片存在和产物哈希。
- 多页检查发现标题落在页末；已修正标题 keep-with-next，以及紧邻题注的表格末行/图片段落分页约束，并重新通过真实排版测试。
- Python 新增测试覆盖并发版本冲突、历史恢复、克隆内部关联、重复区块、题注、缺失数据、不可用引擎拒绝、来源样式清除、AI 遗漏补全、无效/过长文档拒绝。
- 原库 89 项测试继续通过；前端 TypeScript/Vite 构建及新增 Python Ruff 检查通过。构建提示 PDF.js 产物较大，不影响运行；尚未做大文档虚拟化和性能压测。

## 未验收范围

Windows Microsoft Word 适配器未经本环境实际运行；WPS 尚无可用自动化适配器。AI 只进行了本机模拟模型服务的协议集成验证，没有实际外部模型凭据，不能宣称语义转换准确率已通过。字体替代、合并单元格、浮动形状、复杂源 DOCX 保真导入、逐项 AI 接受/拒绝，以及旧版模板迁移不在本次已交付能力中。

## 复现

按 README 启动，安装 Playwright 后运行：

```bash
STUDIO_TEST_URL=http://127.0.0.1:4177 python studio/v2/tests/browser_smoke.py
STUDIO_TEST_OFFICE=1 python -m pytest tests studio/v2/tests -q
```

浏览器脚本默认使用 `/usr/bin/chromium`，可通过 `STUDIO_CHROMIUM` 指定。Office 测试需要 `soffice` 或 `STUDIO_SOFFICE`，使用真实二进制，不以模拟结果替代。截图与生成文件位于被 Git 忽略的 `evidence/`，执行后可重新产生。
